## Implemented composition (compiled, not observed natively)

`InsertionWatchdog` starts a separate message-only `ClipboardGuardian` and a worker. Only the worker/target tree enters the kill-on-close Job Object. The guardian retains an independent complete RAM snapshot before the worker permit. Retained Process handles are duplicated between roles; no arbitrary-PID attach is exposed. The guardian pumps its HWND independently, waits for the worker HANDLE to become signaled, and preserves its RAM/control channel on failed recovery rather than being killed with the worker.

The worker uses the existing hash/native-header-pinned direct-child factory, exact owned A/B identity, actual SQLite `SnippetStore`, actual Presentation `InsertionService`, and linked shipping `ClipboardPasteDispatcher`/CsWin32. Identity sources are explicitly allowlisted, not wildcard-linked to unrelated callback hosts. The positive composition expects fixed Unicode/CRLF target verification, empty sibling B, one dispatch, one persisted usage credit, and a concurrent Busy result. A synchronously finished refusal is never automatically retried. The second scene stops after a completed clipboard swap **before any input**, allowing the coordinator to perform an actual worker/job abort and request independent restoration.

The prototype partial `GuardedClipboardTransaction` supplies the atomic seam unavailable through shipping `IPasteDispatcher`: one `OpenClipboard` lock spans fresh guardian identity + actual original owner/sequence validation, complete snapshot and mutation. Shipping snapshot/representation/privacy helpers are reused; transaction sequencing differs and is **not shipping-method equivalence evidence**. Normal restoration checks actual owner/acknowledged epoch under one lock. Stopped-worker recovery additionally recognizes only empty or exact permitted run-marked synthetic publication/partial-original restoration states. A partial-original state requires the exact per-run marker token, guardian owner, and byte-for-byte subset of the independent original capture; an unmarked original-byte match is not accepted. Owner HWND alone and epoch arithmetic are never ownership proof. Foreign owners/unrecognized added or modified representations refuse restoration.

Incomplete/skipped/capped captures and nonzero/malformed/incompatible-length privacy markers refuse before first clear. Supported original bytes are preserved **plus the three declared protective privacy markers and `SmartSnippets.018.PrivateInsertionOwnership` (16-byte per-run token)**; identical original format-set equality is not promised. Restore writes the ownership marker first and retains it on success/failure, so killed/partial restores remain recognizable without guessing from owner HWND or unknown partial-original matches. Existing ownership-marker captures refuse before mutation. Publication explicitly sets `CF_LOCALE` to en-US (0x0409); expected ANSI/OEM bytes use that locale�s queried code pages, not user-default or active-layout guesses. Exact OS-synthesized bytes/handle sizes still require private native proof; no padding is guessed. Recovery reuses one current snapshot per lock and does not reject sequence changes caused by its own materialization.

Original RAM buffers are zeroed only after verified settlement (or before mutation permission). Clipboard payloads never enter logs/stdout/files; the SQLite fixture contains only fixed synthetic snippet text. File diagnostics use the existing owner-only directory creation before writes. Child private evidence tokens are forwarded by the coordinator (no user paths); retained diagnostic directories/SQLite fixtures still require operator cleanup. Logging is disabled at the Core boundary to avoid raw migration exception paths.

The current-user-only recovery pipe `ss-insertion018-<run GUID>` accepts bounded `retry` requests and returns fixed status; it cannot override owner/state checks or discard the backup. Actual reads and writes are cancellation-bounded; each recovery client is unconditionally disconnected, including broken connections. The pre-arm wait is bounded. On failure, stop/reap the worker first, attempt the bounded guardian recovery handshake even after a reap race, and report `RECOVERY_PENDING` only without verified settlement. Preserve the guardian while unsettled. There is no blanket foreign-owner restoration or forced clipboard-loss option.

The focus seam yields before any mutation to establish the concurrent Busy check, then returns Direct only for an already-foreground exact quiet owned target. It never calls shipping RestoreFocusAsync, SetForegroundWindow or AttachThreadInput. SQLite fixture setup precedes requesting owned focus.

The native input wrapper refuses held input instead of calling shipping generic modifier release. It checks a visible window station, current input desktop, 1.5-second idle, all VKs/buttons released, and immediate exact owned target identity. **Real partial SendInput remains KEYBOARD_RECOVERY_PENDING**: count alone does not identify accepted events; the code does not synthesize potentially unowned key-ups. Exclusive/quiet screen ownership is a precondition, not proof against simultaneous physical same-key input. Hard-abort testing is only before dispatch, not during real key injection.

Run test projects sequentially. The prototype CPM file overrides this build graph only; production project/package configuration and source are unchanged. Direct dependencies: CsWin32 **0.3.367**, CommunityToolkit.Mvvm **8.4.2**, Microsoft.Data.Sqlite **10.0.14**; tests use Microsoft.NET.Test.Sdk **18.11.0**, xunit **2.9.3**, VS runner **3.1.5**. Therefore the global command-line `-p:NoWarn=` is mandatory, not a warning suppression. Its omission was tested and rejected.
