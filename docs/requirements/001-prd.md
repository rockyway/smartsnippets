# Smart Snippets — Requirements Specification

## 1. Overview

**Smart Snippets** is a small Windows desktop utility for storing, organizing, finding, and inserting reusable text into other applications.

The primary workflow is:

1. Place the text cursor in a target application.
2. Press a configurable global hotkey.
3. Find a snippet in a centered popup.
4. Select it using the keyboard or mouse.
5. Insert its text into the original target application.

A separate main application window provides snippet management, folder management, and settings.

### Required technology

- **Application:** .NET 10 with WinUI.
- **Release build:** Native AOT.
- **Storage:** Local SQLite database.

**Proposed assumptions:** WinUI means WinUI 3; snippets contain plain text; folders are single-level; data is local to the current Windows user. These assumptions require confirmation before implementation.

---

## 2. Objectives / Goals

| Objective | Measurable goal |
|---|---|
| Fast access | Open the popup within 300 ms when the application is already running. |
| Keyboard-first operation | Complete search, selection, and insertion without requiring a mouse. |
| Immediate reuse | A newly saved snippet becomes available in the existing popup without reopening it. |
| Responsive search | Return filtered results within 150 ms for a library of 10,000 snippets on an agreed reference machine. |
| Reliable storage | Preserve saved snippets, folders, settings, and usage statistics across application restarts. |
| Predictable insertion | Insert the selected text exactly once into the original target, or report failure without silently redirecting insertion elsewhere. |
| Lightweight deployment | Produce a working Native AOT release build using the agreed UI and SQLite dependencies. |

Performance targets are proposed acceptance targets, not established platform guarantees.

## 3. Detailed Requirements

### 3.1 Snippet data model

Each snippet shall contain:

| Field | Requirement |
|---|---|
| ID | Stable, unique internal identifier. |
| Text | Required multiline plain text; preserve Unicode, whitespace, and line breaks. |
| Label | Required display name, automatically suggested and user-editable. |
| Folder | Optional reference to one folder. |
| Tags | Zero or more tags, entered as comma-separated values. |
| Created date | Automatically recorded on creation. |
| Updated date | Automatically changed when snippet content or organizational fields change. |
| Last used date | Recorded following successful insertion. |
| Usage count | Incremented following successful insertion. |

**Proposed label-generation rule:**

- Interpret “first fragment from tag” as the first nonempty comma-separated tag.
- If no tag exists, use the first nonempty line of snippet text.
- Limit the generated label to 60 characters.
- Once the user edits the label, subsequent text or tag edits shall not overwrite it automatically.

**Tag normalization:**

- Trim leading and trailing whitespace.
- Ignore empty entries.
- Deduplicate tags case-insensitively.
- Preserve a readable display form.
- Commas act as separators; commas inside individual tag names are outside the initial scope.

### 3.2 Manage snippets

The main application shall support:

- Listing and searching snippets.
- Creating, viewing, editing, and deleting snippets.
- Editing text, label, folder, and tags.
- Creating a folder directly from the snippet editor.
- Automatically selecting an inline-created folder for the current snippet.
- Confirming destructive deletion.
- Warning before discarding unsaved changes.

Validation shall reject empty text and empty labels after trimming for validation purposes. Validation shall not trim or otherwise modify the stored snippet text.

Duplicate snippet labels and duplicate text are permitted.

### 3.3 Manage folders

A dedicated folder-management screen shall support:

- Create.
- Read/list.
- Rename.
- Delete.

**Proposed rules:**

- Folder names must be nonempty and unique case-insensitively.
- Snippets without a folder appear under **Unfiled**.
- Deleting a folder moves its snippets to Unfiled after confirmation; it does not delete those snippets.
- Folder renaming is reflected immediately throughout the application.
- Nested folders are outside the initial scope.

### 3.4 Application lifecycle and global hotkey

- The default global hotkey shall be **Ctrl+Shift+Space**.
- Users shall be able to configure a replacement shortcut.
- The application shall validate shortcut registration and explain conflicts.
- A failed shortcut change shall preserve the previously working shortcut.
- The application shall remain available in the background while global access is enabled.
- Closing the main window shall not unintentionally terminate global-hotkey functionality.
- A clear **Exit** command shall terminate the application and unregister its hotkey.
- Only one application instance shall manage the global hotkey and database.

**Proposed lifecycle behavior:** Provide a notification-area icon with commands to open the main window, open settings, and exit.

### 3.5 Global popup

When triggered, the popup shall:

- Capture the identity of the foreground target window before taking focus.
- Open centered within the working area of the monitor containing that target.
- Focus its search textbox automatically.
- Display snippet **Label**, **Folder**, and **Tags**.
- Visually indicate the selected snippet.
- Remain within the monitor’s usable bounds.

**Keyboard behavior:**

| Action | Behavior |
|---|---|
| Up / Down | Move between visible snippets. |
| Enter | Insert the selected snippet. |
| Escape | Close the popup without insertion. |
| Tab / Shift+Tab | Navigate accessible controls. |

Mouse activation of a snippet shall perform the same insertion action as Enter.

In folder layout, folder headings shall be distinguishable from selectable snippets.

### 3.6 Search

The search textbox shall provide free-text filtering across:

- Label.
- Snippet text.
- Folder name.
- Tags.

**Proposed search semantics:**

- Match case-insensitively.
- Treat whitespace-separated terms as an AND query: every term must match at least one searchable field.
- Support substring matching.
- Apply filtering as the user types.
- Display a clear empty-results state.
- Preserve the current sort and layout while searching.

An empty search shall display all snippets.

### 3.7 Popup toolbar

The popup shall provide accessible, icon-based controls with tooltips for:

#### Layout

Switch between:

- **Flat:** One snippet list.
- **Folder:** Snippets grouped by folder, including Unfiled.

#### Sort

Offer:

- Last used.
- Usage count.
- Created date.
- Updated date.

**Proposed defaults:**

- Descending order for all four options.
- Never-used snippets appear after used snippets when sorting by last used.
- Equal values use label and then ID as deterministic tie-breakers.
- Layout and sort choices persist across sessions.

#### Add snippet

- Open a snippet editor without dismissing the popup.
- Preserve the original insertion target while the editor is open.
- On save, refresh the popup and select the new snippet.
- Make the new snippet immediately available for insertion.
- If the current search would hide the new snippet, clear the search so it is visible.
- On cancel, retain the popup’s previous state.

#### Open main application

Open or activate the main management window.

**Interpretation:** “Full screen app” means the full management interface; exclusive fullscreen operation is not required unless explicitly confirmed.

### 3.8 Insert text into the target application

The insertion workflow shall:

1. Retain the original target window.
2. Dismiss the popup.
3. Restore focus to the target where possible.
4. Insert the selected snippet at that application’s current insertion point.

Additional requirements:

- Preserve multiline text and Unicode.
- Prevent repeated insertion caused by duplicate activation events.
- If text is selected in the target, use the target application’s normal replacement behavior.
- Never insert into the snippet editor or another Smart Snippets window accidentally.
- Do not search for another target if the original target becomes unavailable.
- Show an actionable failure message when insertion cannot be completed.
- Update usage statistics only after the insertion mechanism reports success.

The implementation shall validate an appropriate insertion mechanism, including clipboard-based paste if necessary. Clipboard restoration, focus handling, and failure behavior must be explicitly designed and tested.

**Limitation:** An arbitrary target application may not provide confirmation that it consumed the text. Usage statistics shall therefore reflect successful dispatch, not guaranteed application-level acceptance.

### 3.9 Settings

#### Text size

Support:

- Small.
- Medium.
- Large.
- Custom.

Proposed values are 12, 14, and 18 device-independent units, with a custom range of 10–32. Exact values require design approval.

Apply sizing consistently to snippet lists and editable content without clipping controls.

#### Theme

Support:

- Light.
- Dark.
- System.

Apply changes without restarting. System mode shall follow system theme changes.

#### Start at login

- Allow the user to enable or disable automatic startup at Windows sign-in.
- Persist the preference.
- Explain any failure to apply the setting.
- Proposed behavior: Start in the background without opening the management window.

#### Hotkey

Provide shortcut capture, conflict validation, and restoration of the default shortcut.

### 3.10 Persistence and error handling

- Store application data in a per-user local location.
- Use transactions for related changes.
- Enforce valid folder references.
- Maintain a database schema version and migration strategy.
- Keep usage updates separate from content-update timestamps.
- Preserve unsaved editor content when a save fails.
- Present clear errors for database access, migration, hotkey registration, and insertion failures.
- Avoid logging snippet text by default.

No network service shall be required for core functionality.

---

### 3.11 Import and export

- Import JSON exports from TermFlow v1, Rephlo 1.3, InkSpoke v2 and Smart Snippets native v1; detect format and refuse unknown versions before reading entries.
- Export the whole saved library, including empty folders, as compact versioned native JSON. Unsaved editor changes are not included.
- Skip third-party duplicates by line-ending-normalized text; native duplicates use normalized text, resolved label, folder key and ordered normalized tags. Keep imported TermFlow/native dates and usage; usage saturates at int.MaxValue.
- Match folders case-insensitively or create them; invalid folders become Unfiled. Apply the existing label, tag and validation rules; assign new database ids.
- Import atomically in one transaction with one isolated-subscriber change event; export via a same-folder temporary file and atomic replacement. Cancellation changes nothing; show counts or specific refusal/failure messages without logging content or paths.
- Accept UTF-8 .json files up to 32 MB and the calibrated per-file entry limit; refuse exports exceeding either limit so every written file is importable. See plan [010](../plan/010-import-export-snippets.md) §4.3 for exact formats, limits and messages (scope added 2026-10-28).

## 4. Scope & Constraints

### Included

- Local plain-text snippet management.
- Single-level folder management.
- Comma-separated tags.
- Global-hotkey popup.
- Keyboard and mouse selection.
- Search, grouping, sorting, and usage tracking.
- Text insertion into supported Windows applications.
- Theme, text-size, hotkey, and startup settings.
- Import of snippet files from TermFlow, Rephlo and InkSpoke, and export/import of the whole library in Smart Snippets' own JSON format (added 2026-10-28, plan 010).

### Excluded from the initial release

- Cloud synchronization and accounts.
- Shared/team libraries.
- Rich text, images, and attachments.
- Template variables, scripting, and macros.
- Clipboard history.
- Nested folders.
- Guaranteed insertion into every application or elevated process.

### Technical constraints and validation gate

Before full implementation, a small technical prototype shall demonstrate:

1. A .NET 10 WinUI application published with Native AOT.
2. SQLite CRUD operations in that published build.
3. Global-hotkey registration and popup activation.
4. Focus restoration and Unicode text insertion.
5. Startup registration using the selected packaging approach.

If the required technology combination cannot meet these conditions, document the blocker and obtain approval before changing the stack. A non-AOT build shall not be treated as satisfying the requirement.

---

## 5. Success Criteria

The initial release is accepted when:

- All snippet and folder CRUD workflows pass functional tests.
- Data and settings survive restart without loss.
- The popup supports the complete keyboard-only workflow.
- Each toolbar action behaves as specified.
- A snippet created from the popup can be inserted immediately.
- Search and popup latency meet the agreed performance targets.
- Successful dispatch increments usage count once and updates last used.
- Cancellation and failed dispatch do not increment usage.
- Unicode, multiline text, selected-text replacement, and duplicate-activation protection pass testing.
- Theme and text-size changes do not make essential controls inaccessible.
- Hotkey conflicts, unavailable targets, and database failures produce understandable feedback.
- A compatibility matrix records insertion results for an agreed set of text editors, browser inputs, office applications, and terminal applications.
- The release artifact passes the Native AOT technical validation gate.

## 6. Decisions Required Before Implementation

1. Confirm the meaning of “label auto clip first fragment from tag.”
2. Confirm single-level folders and the folder-deletion behavior.
3. Approve label length, text-size values, and search semantics.
4. Select supported Windows versions, CPU architectures, and packaging/distribution approach.
5. Define the supported target-application matrix and elevated-window policy.
6. Approve clipboard preservation behavior if clipboard-based insertion is used.
7. Agree on the reference machine for performance acceptance.
