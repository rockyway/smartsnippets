# Popup polish 2 — single native frame and editor spacing

Scope: user feedback on dc36d8a; plan 006 popup surface/editor only. No insertion, schema or foreground-policy changes.

## Evidence and limits

- Feedback screenshot `popup-feedback2.png`: bright outer perimeter plus inset grey rounded perimeter, with different corner contours.
- `PopupWindow.xaml:9` draws the inset line: RootGrid BorderThickness=1, PopupBorderBrush and CornerRadius=8. `App.xaml:14,30,46` defines that brush as dark #606060, light #909090, or system WindowText in high contrast. Thus the dark-theme WHITE outer line is **not** this brush. There is no second XAML perimeter border, outer focus visual, backdrop or custom shadow in this window. Search focus is confined to SearchBox.
- `PopupWindow.xaml.cs:53-57` installs a borderless presenter and calls RoundPopup only during construction. `WindowSurface.cs:23-29` correctly passes DWMWCP_ROUND=2 and DWMWA_COLOR_NONE=0xFFFFFFFE, but discards HRESULTs. Prewarm Show(false), three visible-show routes, activation, cloak completion and theme/title-bar updates never reassert this policy. No app code sets WS_BORDER/WS_THICKFRAME independently (NativeMethods contains no style getter/setter).
- The white pixels are outside the XAML perimeter, in the native/WinUI window-surface path. Static code and a screenshot cannot prove whether DWM retained/reset its frame or WinUI's backing surface shows through outside the rounded XAML root. Specifically, COLOR_NONE is already correct; changing its spelling is not a fix. Exact attribution between those native paths remains **PENDING-USER** until an authorized desktop inspection. Do not report it as measured or resolved by unit tests.
- Confirmed structural defect: two independent corner/surface owners (borderless native HWND plus rounded/inset XAML border), with unverified one-shot native suppression. Microsoft's [corner guidance](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-rounded-corners) notes the dependence on native frame geometry; [DWMWA_BORDER_COLOR](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute) supports explicit COLORREF and requires applications to handle state changes. [WinUI issue 9621](https://github.com/microsoft/microsoft-ui-xaml/issues/9621) also documents artifacts with SetBorderAndTitleBar(false,false); it is supporting context, not proof about this screenshot.
- `PopupWindow.xaml:39`: Cancel and Save occupy adjacent Auto columns with no ColumnSpacing (default zero). EditorOverlay also has no RowSpacing. Shared SnippetEditor already uses 12-DIP field groups, 8-DIP footer/InfoBar spacing and 8-DIP action spacing.

## Chosen fixes

1. **DWM alone owns the perimeter and clipping.** Retain the presenter's native border, remove its title bar; keep non-resizable/topmost policy. Remove RootGrid border AND independent CornerRadius, filling the client rectangle with the themed background. DWM ROUND supplies a single shared outer clip (8px at 100%, system-DPI-scaled), so there is no second XAML curve to mismatch or expose a backing sliver. Set explicit neutral COLORREF (#606060 dark / #909090 light), or system WindowText in high contrast. No accent/default white border, no nested XAML fallback. On older Windows unsupported attributes are logged, not silently claimed as rounded.
2. Reapply after presenter construction, immediately before/after every Show (including cloaked warmup), after uncloak, activation, effective-theme and accessibility/system-color changes. Do not bypass PopupShowCoordinator. Record failed DWM HRESULTs without content/titles. Use LibraryImport only, no reflection. Pure color/COLORREF policy belongs in Presentation with focused tests.
3. Add 8-DIP column spacing to popup Cancel/Save, 8-DIP editor row spacing and title/subtitle spacing; increase popup error/confirmation action spacing to 8. Class sweep: shared editor actions/InfoBar and Folders rows already use 8; Settings Import/Export live in an 8-spaced panel; built-in ContentDialog owns native button spacing. Snippets inline folder Cancel/Create has only 4 and will be normalized to 8. Icon toolbars/chips are not dialog action rows.
