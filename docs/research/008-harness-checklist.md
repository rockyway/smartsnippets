- [x] **P0 — Dataset (generated, deterministic).** `New-PerfLibrary -Count $PerfLibrary -Seed 42` starts the app once on an empty temporary profile so the schema exists, exits it, then inserts through `sqlite3` in one transaction: - **Folders:** 50 (`Perf folder 01` … `Perf folder 50`). - **Snippets:** 10,000. 9,000 spread evenly over the 50 folders (180 each), 1,000 Unfiled. - **Text** from a fixed 2,000-word English-like vocabulary: 60 % short (20–200 characters, one line), 30 % medium (200–1,000 characters, 2–8 lines), 10 % long (1,000–4,000 characters, 10–40 lines). About 5 % contain non-ASCII characters (accents, CJK, emoji). - **Labels:** 70 % custom (`label_is_custom=1`, 2–5 vocabulary words), 30 % auto (the first line of the text, truncated as the app does). - **Tags:** 0–3 per snippet from a 100-tag vocabulary, in the store's normalised format. - **Usage:** `usage_count` 0–500 with a long tail (most 0–5), `last_used_at` within the last 365 days or NULL for unused, `created_at`/`updated_at` spread over two years, so all four sorts have real work. - **Planted search terms** (no vocabulary word, label, tag or folder name contains them, so substring matching cannot add hits): `alpha` in exactly 1,000 snippets (spread over text, labels and tags), `bravo` in 1,000, both in exactly 100. Counts are asserted by SQL before measuring.
- [x] **P1 — Popup ready at 10k (pass/fail).** First open after a `--background` start, then 20 opens (10 in flat layout, 10 in folder layout), each from Notepad with Esc between. Pass: **every** `popup_ready_ms` sample ≤300 ms. Median/p95/max reported. - **Why pass/fail at 10k, not informational:** AC13 (master `001:83`) sets search at 10k and the popup at ≤300 ms without naming a library size. The popup's ready time grows with the library (it materialises the list), 006 designs its pipeline and prewarm for 10k (006 R4), and judging popup and search on the same dataset makes AC13 one consistent condition. A small-library-only pass bar would leave the popup target unproven at the only scale the programme agreed. E10 keeps the small-profile check as well.
- [x] **P2 — Search end to end (pass/fail).** In the open popup the script sets the search box text in one step with UIA `ValuePattern.SetValue`, so each change produces exactly one `popup_search_ms <int> layout=<flat|folder> results=<n>` line, and waits for that line. Queries: | Query | Change | Expected `results` | |---|---|---| | Q1 one common term | empty → `alpha` | 1,000 | | Q2 two-term AND | empty → `alpha bravo` | 100 | | Q3 no match | empty → `zzqxv` | 0 (empty state shown) | | Q4 clearing the query | `alpha bravo` → empty | 10,000 | Each query runs **20 times in each layout** (4 × 2 × 20 = 160 samples), in a fixed interleaved order; the precondition text for Q4 is set first and its own line is not counted. `results=<n>` must equal the expected count (else FAIL: the measurement did not measure the dataset). Pass: **median ≤150 ms in every (query, layout) cell**. p95 and max are reported for every cell; they are not pass conditions, but any p95 above 300 ms is raised to the user.
