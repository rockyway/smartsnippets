## 2. Current dependency & blocker snapshot (as of 018 in-progress)

- **Measured so far (`016` + follow-up):** Selected Windows x64 (`ProbeManualWindowsPackages=true`) and Apple Silicon macOS (`osx-arm64` pinned source-built backend) Native AOT builds pass with zero suppressed IL warnings; separate native headless processes pass SQLite bootstrap, v1→v2 migration, CRUD, settings, source-generated JSON, and true DB permission-denial follow-up checks on both hosts; bounded authorized basic GUI window smoke passed on both hosts without input/clipboard mutations.
- **Still incomplete in 018:** Representative multi-window XAML/warmup/external beside-window hover (**FG3**), native shortcut/exact-window AX identity/pasteboard safety/single-flight insertion (**FG4**), full diagnostic stream privacy & clipboard/startup recovery (**FG5**), and early mobile strict-AOT/keyboard-host risk check (**T7 / FG6**).
- **Unapproved dependency workarounds:**
  - macOS 37-file source-built backend overlay (`da217df23...` in `016`) is **probe-only, not approved for production**.
  - Windows `ProbeManualWindowsPackages=true` works around default Uno helper `IL2059` and requires explicit production sign-off.
- **Mobile strict Native AOT & host constraints:**
  - **Android `XA1040`:** Official Microsoft `.NET for Android` documentation (https://learn.microsoft.com/en-us/dotnet/android/messages/xa1040) marks `PublishAot=true` / NativeAOT **experimental and not supported for production use**. Neither Mono AOT (`RunAOTCompilation=true`) substitution nor `XA1040` warning suppression is permitted without an explicit owner requirement decision (`018 T7` / `022 T1`).
  - **iOS & host readiness:** Mobile workloads are currently absent (`NETSDK1147`), Apple Silicon Mac disk headroom is ~7.7 GiB free, and iOS custom keyboard extension (`com.apple.keyboard-service`) Native AOT support plus empirical 10k-snippet `phys_footprint` / device-dependent Jetsam headroom are unknown until measured on physical hardware (no universal fixed MB ceiling exists).
  - **Mobile security, network & receipt invariants:** Android routes password/sensitive fields to active custom IMEs (requiring explicit `EditorInfo` password/PIN/`NO_PERSONALIZED_LEARNING` snippet & context suppression, distinct from iOS system-keyboard substitution); iOS `insertText` (`Void`) and Android `commitText` (`bool` IPC return) indicate attempted native dispatch rather than target persistence; host insertion and receipt `rename` cannot commit atomically (providing at-most-once reconciliation per `(libraryId, snippetUid, projectionGeneration, receiptId)` receipt with an explicit non-replayed `+0` pre-rename window); and because iOS uses no network entitlement (`RequestsOpenAccess=true` enables extension networking), zero-network compliance requires static source/symbol/dependency + runtime packet audits alongside Android's `INTERNET` manifest omission.
